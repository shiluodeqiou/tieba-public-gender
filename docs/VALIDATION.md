# 验证记录

日期：2026-10-12（Asia/Shanghai）。版本：1.0.3。

## 已实际检查

- 在内置浏览器打开用户反馈的真实电脑帖子，确认它使用新版 Vue 页面；旧选择器匹配 0 个作者，新选择器 `.user-info .name-info > a.head-name` 匹配 11 个作者位置，包含主楼、回复和楼中楼。
- 新版作者主页链接提供 `id=tb.*` 公开账号标识；头像、外围链接和正文中的提及不作为作者位置。
- 不携带登录 Cookie 请求 `/home/get/panel?ie=utf-8&id=...`，得到 HTTP 200、`no: 0`、`data.sex: "male"`。返回的 `data.portrait` 与请求标识一致，但附带 `?t=数字时间戳`，已据此增加规范化和严格核对。
- 1.0.0 发布前曾匿名请求 `un=...`：两个样本均为 HTTP 200、`no: 0`，分别返回 `female` 和 `male`；`data.name` 与请求账号匹配。
- 未将完整资料响应、真实账号样本或帖子正文纳入项目测试及交付文件。
- 阅读 Tampermonkey 官方请求文档，确认 `anonymous` 和 `@connect` 的用途。由于匿名请求会进入 fetch 模式，脚本另设取消计时器，不只依赖扩展的 `timeout`。
- 用户已确认 1.0.1 的标记有效；按其反馈，1.0.2 移除右下角浮窗，保留昵称标记及油猴菜单控制。
- 对 1.0.2 的审查复现了三项问题：重试复用旧请求、冷却结果保存五分钟、切换帖子后继续查询旧作者。1.0.3 为这三项问题增加回归检查，并修复任务取消、自动恢复与缓存行为。

## 自动化检查

在 Windows、Node.js 24.15.0 下，`npm run check` 语法检查通过，`npm test` 的 **34 项测试全部通过**（0 失败）。检查覆盖：

- 旧版账号字段与显示昵称分离，楼中楼缺少账号时不回退到主楼作者。
- 新版嵌套作者链接、主楼/回复/楼中楼、重复 portrait 查询合并，排除头像、外层链接和正文提及。
- 公开账号标识格式、时间戳后缀核对、错账号拒绝，以及账号名与 portrait 的缓存分离。
- 已知/未知枚举、接口错误、私密资料及异常 JSON。
- 请求参数编码、匿名配置、拒绝访问、重定向、超时取消与限流暂停。
- 缓存到期、条目上限、损坏存储、长 portrait 恢复及重复账号查询合并。
- 动态回复、节点复用、标记去重，以及脚本自己的页面修改不造成重复查询。
- 初始关闭、菜单状态更新、设置保存、未知隐藏和通过菜单原地重新查询；页面不添加浮窗。
- 关闭后跳过排队请求，不缓存关闭结果，迟到响应不恢复标记；重新开启可恢复查询。
- 无作者时不发送请求；油猴请求接口缺失和访问失败通过标记的悬停说明显示。
- 列表进入帖子的 SPA 导航，以及离开帖子后的标记清理。
- GM 接口只注入词法作用域、没有挂在 `window` 上时，直接执行同一份可安装脚本仍能查询和显示标记。
- 重试实际取消旧请求；迟到回调不能覆盖新标记、写回旧缓存或删除新请求的去重记录。
- 整批取消旧任务后，不为每个已取消任务额外等待 900 毫秒；新请求仍遵守速率限制，重试不会绕过冷却。
- 用虚拟时钟验证完整的一分钟冷却：期间不请求，到期后排队账号和触发限流的当前作者均自动恢复查询，无需刷新。
- 站内换帖取消旧请求与排队任务；即使当前帖未变化，已移除作者的请求也在发送前跳过。
- 最近遇到的吧友优先保留，顺序可持久化，读取不延长到期时间；刷新或新帖可直接读取缓存，无需网络权限。
- 升级保留有效资料缓存，自动丢弃旧版本遗留的冷却、限流、取消状态。

运行结果以 `npm run check` 和 `npm test` 的实际输出为准。测试使用合成账号和模拟网络响应，不联系外部服务。

## 安装后快速验收

1. 点击项目安装链接更新至 1.0.3，刷新电脑网页版帖子；页面应没有右下角浮窗。
2. 等待查询，昵称旁应出现男、女或未知标记；将鼠标停在未知标记上查看原因。
3. 从油猴菜单点击“标记功能：已开启（点击关闭）”，确认菜单变为“已关闭”且标记移除；再次点击恢复。刷新后开关设置应保持。
4. 展开楼中楼，确认新作者也能显示标记；正文中的被回复者和 @ 提及不会被误当作作者。
5. 从油猴菜单切换未知标记，再使用“清空性别资料缓存并重新查询”，确认标记正常变化，无需重新加载整页。
6. 可选：从列表通过站内跳转进入帖子检查标记出现，再返回列表检查标记消失。
7. 同一吧友在另一帖子出现时，未到期的标记应直接读取缓存；需要立即更新资料时使用重新查询菜单。
