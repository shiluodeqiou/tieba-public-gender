# 验证记录

日期：2026-10-12（Asia/Shanghai）。版本：1.0.0。

## 已实际检查

- 使用不携带登录 Cookie 的匿名 HTTPS 请求，访问贴吧 `/home/get/panel?ie=utf-8&un=...`。
- 两个公开账号请求均返回 HTTP 200 和 `no: 0`；分别观察到 `data.sex: "female"`、`data.sex: "male"`。
- 两次请求的 `data.name` 均与请求账号匹配；其中 `male` 样本的 `data.is_private` 为 `0`。
- 未保存完整资料响应、账号凭据或帖子内容。
- 阅读 Tampermonkey 官方文档，确认 `anonymous` 和 `@connect` 的用途。由于匿名请求会进入 fetch 模式，脚本另设取消计时器，不只依赖扩展的 `timeout`。

## 自动化检查

在 Windows、Node.js 24.15.0 下，`npm run check` 语法检查通过，`npm test` 的 16 项测试全部通过（0 失败）。检查覆盖：

- 账号名和显示昵称分离，楼中楼缺少账号时不回退到主楼作者。
- 已知/未知枚举、接口错误、资料私密、账号不匹配及异常 JSON。
- 请求参数编码、匿名配置、拒绝访问、重定向、超时取消与限流暂停。
- 缓存到期、条目上限、损坏存储及重复账号的请求合并。
- 合成桌面帖子里的主楼、楼中楼、动态回复、昵称节点复用、标记去重和菜单开关。

运行结果以 `npm run check` 和 `npm test` 的实际输出为准。测试使用合成账号和模拟网络响应，不联系外部服务。

## 尚未验证

- 没有在用户的浏览器中安装或启用 Tampermonkey，也没有完整验证登录后的帖子浏览流程。
- 当前环境直接请求一个真实 `/p/` 页面时，得到 HTTP 200 的简化 HTML，其中没有 `p_author_name` 等帖子节点，不能把它当作已验证的实时完整 DOM。选择器参考了公开的历史桌面页面样本，并在合成页面中测试。
- 浏览器扩展中的匿名请求可能受网络、浏览器版本和贴吧策略影响。命令行接口成功不保证所有安装环境均成功。
- 手机/H5、其他增强脚本修改过的布局和未来贴吧改版不在本次验收范围内。

## 安装后快速验收

1. 安装脚本，打开电脑网页版帖子，检查昵称旁是否出现标记。
2. 展开楼中楼，确认新出现的作者也显示标记，正文中的被回复者/@ 提及不被误当作作者。
3. 同一账号多次出现时，应得到一致标记；鼠标悬停可看到用户自填资料说明或未知原因。
4. 从油猴菜单切换未知标记，再清空缓存并刷新，检查菜单行为。
5. 可选：在油猴的脚本存储中检查缓存只有精简字段，没有完整资料响应。
